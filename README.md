# Productivity Log

A React + TypeScript application powered by Vite, plain CSS, and Lucide icons.
The current experience focuses on My Activity Log, Add Activity, independent
Learning Plan creation, and a mock AI Learning Coach with confirmed activity drafts. No backend,
database, or authentication is included.

## Getting Started

Use Node.js 20.19+ (20.x) or 22.12+ and npm.

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. In a development container, use
`npm run dev -- --host 0.0.0.0` and forward the printed port if needed.

## Commands

- `npm run dev`: start the development server with hot reload.
- `npm run build`: run strict TypeScript checks and build into `dist/`.
- `npm run preview`: serve the production build locally after building.

## Local Workflow

My Log is the default landing page. `#/my-log`, `#/add-activity`, and
`#/learning-plans` support direct navigation and browser Back/Forward without a routing dependency. Category,
status, and date filters work together; pagination shows eight sessions per page.
The initial date range is October 2024 to match the supplied sample sessions.
After saving sessions, the log defaults to all dates on reload so new records
are not hidden by the sample date range.

Choose a learning plan and milestone in Add Activity, record time and status, and
optionally add reflections and evidence metadata. For a plan without predefined
milestones, enter the session activity as text; this does not create a required
milestone or manually change plan progress.

Select **Other** to create a learning plan or category. The required custom name
appears directly below its dropdown and is cleared when switching back to an
existing option. Names are trimmed, repeated whitespace is normalized, and
case-insensitive duplicates of built-in or custom names are rejected. The Other
label and its internal dropdown value are reserved. Custom options entered through
Add Activity are created only when the complete session is saved, never on Cancel
or invalid submission.

Save returns to My Log, clears the filters, and opens the table page containing
the new session. Cancel returns without saving.

## Learning Plans

Open Learning Plans in the sidebar to see both built-in and custom plans. Select
New Learning Plan to create one without recording an activity. The form includes
a required name, plus optional description, target skill, and target completion
date. Blank or case-insensitive duplicate names are rejected using the same
validation as Add Activity.

Creating a plan does not create activities, categories, or required milestones.
New plans appear in the list and the Add Activity dropdown immediately and remain
available after refresh. Add Activity prompts for the session category when the
plan has none. Older saved plans without the new metadata remain compatible;
their missing fields display as Not set. Cancel does not save a plan.

This iteration is create-and-list only: no editing, deletion, milestone
management, progress calculation, or external integrations are included.

## AI Learning Coach: Phase 2

Open the floating AI Coach button on any page. The panel supports these prompts:

- What should I learn next?
- Show my recent learning activity
- What am I currently learning?
- Help me add an activity

`AiCoachService` defines the asynchronous service boundary. The current
`MockAiCoachService` produces deterministic replies from the activities and plans
already loaded by the application, including saved custom records. It does not
call a model, Google ADK, or any backend. The three learning-summary and
recommendation prompts remain read-only.

Recommendations are labeled **Mock AI Recommendation** and use recorded sessions,
required milestones, blockers, and next steps. Missing prerequisite order is
explicitly identified as a general suggestion. No official progress percentage
is calculated or inferred. Missing records are reported, not invented.

### Conversational Activity Creation

Select Help me add an activity or describe a session, such as "I studied Azure
for 2 hours today." The mock collector retains supplied values across messages
and asks concise questions about missing or invalid fields. It recognizes common
session phrases, numeric or simple number-word hours, today/yesterday, ISO dates,
and written English dates. It is deterministic pattern matching, not general
natural-language understanding. Labels such as `Learning Plan:`, `Category:`,
`Learned:`, `Blockers:`, and `Next Step:` can disambiguate details.

A separate typed `ActivityDraft` holds incomplete conversation data, including
date, an existing learning plan, milestone/activity, an existing category, hours,
task status, learning reflection, blockers, and next step. Reflection fields must
be supplied explicitly; say none when there are no blockers or no next step.
Supported statuses remain Completed and In Progress. Plans with predefined
milestones require an existing milestone; other plans allow a free-text activity.
Unknown plans/categories are questioned and never created through chat.

When complete, the coach displays a confirmation card:

- **Edit** opens all draft fields for correction and invalidates confirmation
  until the corrected draft is reviewed again.
- **Cancel** discards the pending draft without writing to storage.
- **Confirm & Save** revalidates the draft, converts it to `NewActivityInput`, and
  uses the same App/repository save flow as manual Add Activity. It returns to My
  Log and displays "Activity added successfully." only after persistence succeeds.

A synchronous submission guard prevents double-click duplicates. Failed writes
retain the draft and display an error for explicit retry. The mock service can
only prepare drafts; it receives no persistence callback. No chat message, even
"save" or "confirm," performs a write. Only the confirmation button may do so.
No milestone definitions or official progress are modified.

Optional evidence is metadata only (filename, MIME type, size; at most 10 MB).
File contents are never read, uploaded, or stored in localStorage. The draft
editor can attach or remove metadata.

Opening, closing, and collecting drafts do not write to localStorage. Chat
history and unsaved drafts stay in React memory across panel toggles/navigation
and reset on refresh. Service errors preserve the current message and leave
manual workflows available. There is no Google ADK, Gemini, backend, cloud
service, authentication, or credential integration in this phase.

## Browser Storage

Activities, custom learning plans, and custom categories persist together under
the versioned localStorage key `productivity-log:data:v1`. Refreshing preserves
them; clearing browser site data removes them. Sample records are used only when
no saved record exists. Storage write errors keep the form open without reporting
success or saving partial options. Unreadable saved data is reported and is not
silently overwritten.

Data access and authoritative validation live behind the typed
`ActivityRepository` contract in `src/data/activityRepository.ts`. The UI receives
records and an async-compatible save callback rather than reading or writing
localStorage itself, allowing a future API implementation without a UI redesign.

Evidence is limited to 10 MB; only file metadata is persisted, not file contents.
No files are uploaded. The UI uses Google Fonts with a local sans-serif fallback.

## Product Principle

**Plan the path. Prove the progress.**

Activities represent learning sessions, not manually entered progress. There is
no progress-percentage field. Future plan progress will be calculated as
completed required milestones divided by total required milestones, with unique
milestones counted once rather than counting repeated sessions as completions.
